### Fix critical sections staying locked after nested use (CompatLib)
- `LeaveCriticalSection` in both `threads_compat.h` copies only unlocked the pthread mutex when the depth counter reached 0, but the mutex is recursive and `EnterCriticalSection` locks it on every enter. After any nested enter/leave the owning thread kept the mutex forever, so a second thread entering the same critical section (memory pools, DMA) blocked for good. This is what made the background audio decode hang.
- Leave now always unlocks and only clears the owner at depth 0. Confirmed with a standalone test: nested enter/leave on one thread, then another thread enters; it blocked before and gets the lock now. Single-threaded behaviour is unchanged.

### Cache decoded sounds in the MiniAudio backend
- A replay of the Victory Valley LAN match with the split FPS log and a `perf` profile showed where the worst stutters come from: the audio update. Every stutter over 200 ms was in "audio" (the simulation has its own spikes of up to about 170 ms), and audio took 2-8 ms of the average frame in battles. The profile showed why: the MiniAudio backend decoded the whole file with FFmpeg every time a sound played (and every time a loop repeated), and FFmpeg probed every demuxer for each file (`*_probe` functions were about 14% of all samples).
- `MiniAudioManager` now keeps decoded files in a cache shared by all sounds that play them, like the Miles and OpenAL backends' file caches. ### MiniAudio: gapless sound loops, music hand-over and stale requests after a reset
- On the Pi a finished in-game music track was sometimes heard starting again before it faded out and the next track began. Map scripts switch tracks when `hasMusicTrackCompleted()` reports a completed loop, fading the old track out.
